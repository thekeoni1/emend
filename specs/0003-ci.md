# 0003: T0b continuous integration

Status: READY (planning, 2026-09-15). The maintainer approved this task on
2026-09-15. It runs after T2 P0 and before T1.
Context: `CLAUDE.md`, `specs/0001-bootstrap.md` ("How this task runs",
"Rules for every phase", and "Close-out push" for the push steps).

## Goal

Every push to GitHub gets an independent build and test on a clean
machine. CI proves the gate's build steps do not depend on this
machine's state.

CI is not a privacy guard:
- It runs after the push, so the local pre-push hook stays the only
  thing that keeps private data off GitHub.
- The private denylist never goes to GitHub, not even as a secret.
- No corpus data ever goes to CI.

## P1: CI mode and workflow

Deliverables:
- `scripts/check.sh --ci`:
  - Runs steps 1 to 7.
  - In place of step 8 it prints `SKIP privacy: --ci (the private
    denylist never leaves the maintainer's machine)`.
  - Combining `--ci` with `--quick` prints the usage line and exits 2.
  - Locally, every push procedure still runs the full gate.
- `.github/workflows/ci.yml`:
  - Trigger: `push` to any branch. No `pull_request`, no schedule.
  - Top-level `permissions: contents: read`. No secret is referenced.
  - One job on a pinned Ubuntu runner label (for example
    `ubuntu-24.04`), never `ubuntu-latest`, with `timeout-minutes: 30`.
  - Steps:
    1. `actions/checkout` pinned to
       `3d3c42e5aac5ba805825da76410c181273ba90b1` (release v7.0.1,
       2026-07-17), with `persist-credentials: false` and the tag in a
       comment beside the SHA.
    2. Install the pinned toolchain explicitly:
       `rustup toolchain install 1.98.1 --profile minimal --component
       rustfmt,clippy --target i686-unknown-linux-musl`. Print
       `rustc --version` and the installed targets.
    3. Run `RUSTUP_AUTO_INSTALL=0 scripts/check.sh --ci`.
  - No caches, no uploaded artifacts, no other actions.

Before any push, locally:
- `scripts/check.sh` in full: all eight steps PASS.
- `scripts/check.sh --ci`: seven PASS lines, then the SKIP privacy line.
- `scripts/check.sh --ci --quick`: the usage line, exit 2.
- The workflow file passes `scripts/privacy.sh` like any tracked file,
  and `grep -n secrets .github/workflows/ci.yml` finds nothing.

Push: follow the close-out push steps in `specs/0001-bootstrap.md`:
- first the hook, `core.hooksPath` and `EMEND_PRIVATE_DENYLIST` checks
  and the full gate;
- then `git push origin main`;
- then `ls-remote` equals local main, and the repository is still
  PRIVATE.

The push needs planning's word and the maintainer's authorisation typed
in the implementing session.

After the push, wait for the CI run on the pushed commit and record it.

- Logs, in `records/logs/t0b-p1/`:
  - `gate.log`: the full local gate.
  - `ci-local.log`: the `--ci` run and the `--ci --quick` run.
  - `push.log`: the push steps, with every check evaluated once.
  - `ci-run.log`:
    - `gh run list --workflow ci.yml --commit <pushed sha>` and
      `gh run view <run id>`, showing conclusion `success` and each
      step's result;
    - from `gh run view <run id> --log`, only the lines that start with
      `PASS`, `SKIP` or `FAIL`, plus the runner label and the
      `rustc --version` line. Never the full log.
  - `scan.log`: per the scan rules.
- Record commits stay local until the next authorised push.
- Acceptance:
  - The CI run on the pushed commit concludes `success`.
  - Its output shows the seven PASS lines and the SKIP privacy line, in
    order.
  - `gh api repos/thekeoni1/emend/actions/permissions` shows the
    restricted settings.

## P2: prove CI can fail

- In a scratch clone, create branch `ci-negative` from main, with one
  deliberately misformatted line in `tools/xlsx-diff/src/main.rs`. It
  must never reach main.
- Push only that branch. This needs planning's word and the maintainer's
  authorisation, like every push, and the pre-push hook runs as usual.
- Record the CI run on that branch: conclusion `failure`, with the
  failed step's filtered output showing `FAIL fmt`.
- Delete the remote branch with `git push origin --delete ci-negative`
  (the hook skips deletions). Confirm that
  `gh api repos/thekeoni1/emend/branches` lists only `main`, and that
  main's latest CI run is still `success`.
- Logs, in `records/logs/t0b-p2/`: `push.log`, `ci-run.log` (filtered as
  in P1), `cleanup.log`, `scan.log`.
- Acceptance:
  - The failure run is recorded with `FAIL fmt`.
  - Only `main` remains on GitHub.
  - Main's latest run is `success`.

## Out of scope

- Privacy checks in CI. The denylist stays local, and the pre-push hook
  is the guard.
- Corpus data in CI, ever.
- Caching, build matrices, other operating systems, release builds,
  status badges.

## After T0b

Every later push procedure adds one step: once `ls-remote` matches,
record the CI run for the pushed commit
(`gh run list --commit <sha>`) with its conclusion.
